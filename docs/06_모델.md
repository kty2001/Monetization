## 1. 타겟

`target_paid_events_per_episode` = **회차당 구매 건수** = 목록 API의 `nvSumPurchased` ÷ 유료 회차 수. 대여수(`nvSumRented`)는 무료 쿠폰성 이용이 섞여 제외했다.

> **왜 나누는가 (2026-08-13 수정)**: `nvSumPurchased`는 회차당 수치가 아니라 **작품 전체 누적 구매 건수**다. 실측으로 확인했다 — 총 구매수 중앙값 64,764 / 유료 회차수 중앙값 175 → 회차당 397건, 유료 회차 수와의 스피어만 상관 0.405.
>
> 이걸 그대로 타겟으로 쓰면 두 가지 문제가 생긴다.
>
> 1. **해석 오류**: 앱이 "회차당 구매수"로 표시해 단가를 곱하니 회차당 매출이 100배 넘게 부풀려졌다(실사용에서 회차당 1,110만원이 나왔다. 회차당으로 고치니 61,600원).
> 2. **예측 성능 손해**: 총 구매수는 "회차당 인기"와 "몇 화까지 연재했는가"가 섞인 값인데, 후자는 앞 10화로 알 수 없어 타겟의 순수 잡음이 된다.
>
> 유료 회차 수는 `chapter_count`(novel-detail의 총 회차 수 — 회차 수집을 잘라도 보존된다)에서 수집한 선행 무료 회차 수를 뺀 값이다. 유료 회차는 수집하지 않으므로 직접 셀 수 없다.

타겟이 여전히 넓게 퍼져 있어(중앙값 419, 최대 26,642) **`log1p` 공간에서 학습**하고 `expm1`로 되돌린다(`TransformedTargetRegressor`).

**매출(KRW)은 모델이 예측하지 않는다.** 회차 단가가 작가별 계약에 따라 달라 크롤로 확보할 수 없으므로, 앱에서 사용자가 입력한 단가를 곱하기만 한다:

```
회차당 예상 매출 = 회차당 예측 구매수 × 회차 단가
작품 전체 매출   = 회차당 예상 매출 × 유료 연재 회차 수
```

단가는 학습·피처에 일절 개입하지 않고, 상수배라 작품 간 순위도 바꾸지 않는다.

## 3. 피처

모델에 들어가는 것은 **이게 전부**다. 모든 피처는 **선행 무료 구간의 앞 10화**에서만 계산한다.

> **선행 무료 구간**이란: 1화부터 세어 **첫 유료 회차를 만나기 직전까지**의 연속 무료 회차. 단순히 `access_type == "FREE"`로 거르면 안 된다 — 완결 후기가 마지막 회차에 무료로 붙는 경우가 있어(샘플 20건 중 1건 관측) 티저가 아닌 회차가 섞인다. `access_type`이 결측이어도 구간을 끊는다.
>
> 앞 10화로 통일하는 이유: 학습셋의 무료 회차는 플랫폼이 정한 티저(중앙값 25화)이고 추론셋은 작품 전체(중앙값 3화)라, "무료 회차 전체"로 집계하면 같은 피처가 양쪽에서 전혀 다른 것을 뜻하게 된다.

| 피처 | 계산식 | 파이프라인 처리 |
|---|---|---|
| `genres` | 쉼표로 이어붙인 다중 라벨 문자열 | `CountVectorizer(analyzer=쉼표분할, binary=True)` → 17개 토큰 multi-hot |
| `free_views_1_10` | 앞 10화 `view_count` 합 | passthrough |
| `retention_1_to_10` | 10화 조회수 ÷ 1화 조회수 | passthrough |
| `retention_1_to_3` | 3화 조회수 ÷ 1화 조회수 | passthrough |
| `likes_1_10` | 앞 10화 `like_count` 합 | passthrough |
| `comments_1_10` | 앞 10화 `comment_count` 합 | passthrough |

- `retention_*`는 1화 조회수가 0이면 **`NaN`으로 두고 채우지 않는다** — `HistGradientBoostingRegressor`가 결측을 네이티브로 처리한다.
- 수치 피처가 `passthrough`인 이유: 트리 모델은 단조 변환에 불변이라 스케일링·로그 변환이 불필요하다. **선형 모델(`Ridge`/`ElasticNet`) 경로에만** `impute_log_scale=True`로 중앙값 대치 → `log1p` → 표준화를 붙인다. 이걸 빼면 선형 모델이 `free_views_1_10` 하나짜리 베이스라인보다도 나빠진다(총 구매수 타겟 기준 logRMSE 1.226 vs 1.111에서 확인. 회차당 타겟에서도 `Ridge` 0.7964 < 베이스라인 0.8652로 순서 유지).

### 장르 어휘 (학습셋에서 고정된 17개)

```
SF, 게임, 공포·미스테리, 대체역사, 드라마, 라이트노벨, 로맨스, 무협,
스포츠, 연극·시나리오, 일반소설, 전쟁·밀리터리, 중·단편, 추리,
판타지, 퓨전, 현대판타지
```

조합 문자열을 그대로 one-hot하지 않는 이유: 조합 기준으로는 학습 121종 / 추론 316종이라 **추론셋의 15.5%가 미학습 조합**이 된다. 토큰으로 쪼개면 학습 17종이 추론 21종에 모두 포함되고, 어휘가 fit 시점에 고정되므로 추론에만 있는 4개 토큰은 자동 무시된다.

### 피처에서 제외한 것

| 컬럼 | 제외 사유 |
|---|---|
| `total_view_count`, `chapter_count`, `like_count`, `preference_count` | **누수** — 유료작에서는 무료+유료 기간의 누적치라 타겟과 직결된다 (`LEAKY_COLUMNS`) |
| `NovelStats`의 `good_count`, `prefer_count` | **누수** — "현재 시점" 스냅샷이라 유료 시기 값을 분리할 수 없다 |
| `serialization_status` | **분포 불일치** — 학습셋 `완결` 100% / 추론셋 `연재중` 100%로 train/inference 분할과 완전히 교락. 학습 시 상수라 정보량 0, 추론 시 미학습 카테고리 (`EXCLUDED_STATIC_COLUMNS`) |
| `tags` | **분포 불일치** — 결측률이 학습 56.2% vs 추론 35.0%로 달라 결측 자체가 covariate shift |
| `leading_free_episodes` | **메타데이터** — 유료작은 플랫폼이 정한 티저 수(중앙값 25), 무료작은 작가가 쓴 분량(중앙값 20)이라 의미가 다르다. 데이터셋에는 싣되 피처에서 뺀다 |

`service/schema.py`의 `assert_feature_schema`가 데이터셋 저장 전에 컬럼 **누락과 예상 밖 컬럼을 모두** 검출해 학습/추론 간 피처 어긋남을 막는다.

## 4. 모델과 하이퍼파라미터

```python
TransformedTargetRegressor(
    regressor=Pipeline([
        ("prep", ColumnTransformer([
            ("genres",  CountVectorizer(analyzer=genre_tokens, binary=True), "genres"),
            ("numeric", "passthrough", NUMERIC_FEATURE_COLUMNS),
        ])),
        ("model", HistGradientBoostingRegressor(random_state=42)),
    ]),
    func=np.log1p, inverse_func=np.expm1,
)
```

**`random_state=42` 외에는 전부 scikit-learn 기본값**이다(학습된 트리 100개). 튜닝하지 않은 이유는 6절 참고.

> ⚠️ `CountVectorizer`에 넘기는 `genre_tokens`는 반드시 **모듈 수준 함수**여야 한다. 람다로 두면 표준 `pickle` 직렬화가 깨지고, PyInstaller 배포본에서는 `service.model_training`을 `hiddenimports`에 넣지 않으면 **배포본에서만** 언피클이 실패한다. `tests/service/test_model_training.py::test_fitted_pipeline_is_picklable`과 앱의 `--selftest`가 각각 가드한다.

## 5. 분할과 평가 방법

- **분할**: 타겟 10분위 층화 80/20 (`random_state=42`) → train 7,192 / test 1,798. 타겟이 4자릿수 스팬이라 무작위 분할만으로는 고액 구간이 한쪽으로 쏠린다.
- **교차검증**: 5-fold. 표준 scorer는 `expm1` 이후의 원공간 RMSE만 주므로, 폴드별 예측을 직접 받아 로그공간 지표를 계산한다.

| 지표 | 정의 | 보는 이유 |
|---|---|---|
| `log_rmse` | `log1p` 공간 RMSE | 학습이 이 공간에서 이뤄지므로 **모델 간 비교의 기준** |
| `log_r2` | `log1p` 공간 R² | 설명력 |
| `mae` | 원공간 평균절대오차 | 절대 규모 감각 |
| `mdape` | 원공간 절대백분율오차의 **중앙값** | 평균이 아니라 중앙값을 쓰는 건 소수 대형작이 평균을 지배하기 때문 |
| `spearman` | 순위상관 | 다운스트림이 "작품 순위 매기기"라 순위 보존력이 실질적으로 중요 |

|---|---|---|
| 예측/실제 배율 중앙값 | **0.98배** (거의 무편향) | 0.96배 |

## 7. 한계

**(1) 선택 편향** — 학습셋은 "유료 전환에 **성공한** 작품"뿐이다. 전환하지 못했을 작품에도 성공작 분포를 씌우면 체계적으로 과대추정한다. 그래서 예측값은 **"유료 전환에 성공했을 때의 조건부 기댓값"**으로만 읽어야 하고, 전환 확률 자체는 모델링하지 않는다.

**(2) 지지구간 불일치** — 학습셋 `free_views_1_10`의 5~95% 구간은 **1,586 ~ 731,535**인데, 추론 대상 무료작의 **84.0%가 하한 미만**이다(정상 구간은 16.0%뿐). 범위(min~max)로는 99.4%가 학습셋 안에 들어와 아무것도 걸러지지 않으므로, **분위수** 기준으로 밴드를 나눠 `support_band` 컬럼으로 내보낸다. 앱은 이 값을 반드시 노출한다.

holdout에서 밴드별 오차는 정상 1,634건 MdAPE 40.3% / 희박(하한 미만) 71건 44.9%로 차이가 크지 않아 보이지만, **학습셋의 희박 표본이 71건뿐이라 이 수치를 추론셋(84%가 희박)으로 옮길 수 없다.** 6절의 최하위 20% 구간(MdAPE 56.2%, 1.35배 과대예측)이 실사용에 더 가까운 참고치다.

**(3) 티저 조회수 누적** — 유료작의 무료 회차 조회수는 **전환 이후에도 계속 쌓인다**. 나이를 보정해도 격차가 남는다:

| | 1화 게시 후 경과일 | `free_views_1_10` 중앙값 | 일평균 조회수 |
|---|---|---|---|
| 학습셋(유료) | 1,970일 | 185,082 | **105.22** |
| 추론셋(무료) | 679일 | 298 | **0.48** |

원래 격차 621배 중 나이로 설명되는 건 2.9배뿐이고 **219배가 남는다**. 이는 (a) 애초에 인기작만 전환됐다는 선택 편향과 (b) 전환 후 유입된 독자가 티저를 읽어 조회수가 부풀려진 것이 섞인 결과인데, **스냅샷이 1시점뿐이라 둘을 분리할 수 없다**. 전향적(prospective) 데이터 수집이 필요한 근본 이유다([로드맵](04_로드맵.md) "다중 시점 대비").

**(4) 미결 — 피처 기준 회차 수 `N`**

| N | 학습셋 | 추론 대상 | logRMSE | MdAPE | Spearman |
|---|---|---|---|---|---|
| 5 | 9,084 | 18,734 | 0.9487 | 53.0% | 0.894 |
| **10 (현재)** | 8,990 | 11,189 | 0.9036 | 51.3% | 0.892 |
| 20 | 8,800 | 5,737 | **0.8294** | **47.4%** | 0.903 |
| 25 | 7,818 | 4,486 | 0.8457 | 48.1% | 0.906 |

N=20이 8.2% 개선이지만 검색 가능 작품이 절반이 된다(N=25는 오히려 나빠져 20이 최적점). 정확도와 범위의 교환이라 **선택은 보류 상태**다.

**(5) 하이퍼파라미터** — 25조합 랜덤서치 결과 CV logRMSE 0.9221 → 0.9172(0.5%), holdout MdAPE 51.3% → 51.1%로 **여력이 거의 없다**. 성능 한계는 하이퍼파라미터가 아니라 피처 쪽에 있다.
