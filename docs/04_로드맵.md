# 로드맵 (데이터 파이프라인 / 모델링 / 대시보드 / 테스트)

크롤러 이후 남은 작업의 설계를 정리한다. 세부 구현 시 참고용.

## 핵심 결정 사항

- **타겟(라벨) 정의**: Munpia는 실제 매출(KRW)을 공개하지 않는다. 대신 `pl.serial`/`pl.serial_end`(유료 전환작) 목록 API의 `nvSumPurchased`(구매수)를 매출 프록시로 사용한다 — `target_paid_events = purchased_count`. 대여수(`nvSumRented`)는 무료 쿠폰성 이용이 많다고 판단해 제외.
- **학습 대상**: `pl.serial_end`(완결, ~9,249건, 타겟 확정)만 학습에 사용. `pl.serial`(진행 중, ~1,212건)은 구매수가 계속 늘어나는 censored 데이터라 학습 제외, 정성적 검증용으로만 활용.
- **피처 누수 방지 원칙**: 모든 피처는 **무료 회차 데이터에서만** 계산한다. `NovelStats`의 누적 집계(`nvSumHit` 등)는 유료작의 경우 무료+유료 기간이 섞여 있어 타겟과 누수 관계이므로 피처로 쓰지 않고 타겟 산출에만 사용한다.
- **모델링 순서**: ML(회귀) 먼저, `HistGradientBoostingRegressor`가 `total_free_views` 단일 피처 베이스라인을 유의미하게 못 이기고 에러 분석으로 데이터 문제가 아님이 확인될 때만 DL 검토.
- **모델 직렬화**: 신규 의존성 없이 표준 `pickle` 사용 (joblib 미도입).
- **다중 시점 대비**: `data/processed/`는 `run_id`가 아니라 `snapshot_date`(YYYYMMDD)로 파일을 누적 저장(덮어쓰지 않음).

## A. 라벨 데이터 크롤러 (`clawler/paid_runner.py`, `scripts/crawl_munpia_paid.py`)

- `CrawlConfig.section`을 `pl.serial`/`pl.serial_end`로 바꿔가며 목록만 순회(`iter_list_page_items`)하면 구매수를 포함한 item dict를 얻는다.
- 장르가 목록 API에서는 숫자 코드(`nvGnMain`)뿐이라 무료작 데이터셋(문자열 `genres`/`tags`)과 스키마를 맞추기 위해 `novel-detail` 상세 호출은 그대로 유지한다.
- 회차 호출은 비용 절감을 위해 **처음 유료(`free=false`) 회차를 만나면 중단**하는 최적화를 적용할 계획 — 단, "무료 회차가 항상 앞쪽에 연속된다"는 가정이므로 구현 전 20~30개 샘플로 전체 회차를 받아 검증 후 확정한다.
- `CrawlRepository(prefix="paid_")`로 `data/raw/paid_novels_*.csv` / `paid_episodes_*.csv` / `paid_novel_stats_*.csv`에 저장, 기존 `CrawlCheckpoint` 재사용(키: `f"{section}:{novel_id}"`).
- **실행 시점**: nv.free 크롤이 끝난 뒤 시작(동시 부하 방지). 예상 규모 약 10,461건, 6~9시간대.

## B. 정제/피처 엔지니어링 (`service/`)

| 모듈 | 역할 |
|---|---|
| `raw_loader.py` | `data/raw/`에서 각 CSV 접두사별 최신 `run_id` 파일을 찾아 로드 |
| `episode_features.py` | `compute_episode_features(episodes_df)` — 무료 회차 기준 집계(조회수/좋아요/댓글, `view_retention_ratio` 등). 무료작/유료작 데이터셋에 동일 함수 적용 |
| `novel_features.py` | `Novel` 정적 필드(장르/태그/연재상태) + episode_features join. 범주형 인코딩은 여기서 하지 않고 모델 파이프라인(`ColumnTransformer`)에 위임 |
| `target_builder.py` | `NovelStats` → `target_paid_events` 산출 |
| `schema.py` | `FEATURE_COLUMNS`, `assert_feature_schema(df)` — 무료/유료 데이터셋과 추론 스크립트가 공통으로 검증 |
| `build_processed_dataset.py` | `build_free_dataset()`(추론 대상, 타겟 없음) / `build_labeled_dataset()`(학습셋) |

## C. 모델링 (`research/`, `scripts/`)

- 분할: `pl.serial_end` 80/20, 타겟 분위수 층화, 5-fold CV
- 타겟 변환: `log1p`로 학습, `expm1`로 역변환. 지표: 로그공간 RMSE/R²(모델 비교), 원공간 MAE·MdAPE, Spearman 순위상관(다운스트림이 "순위 매기기"이므로)
- 베이스라인: 평균/중앙값, `total_free_views` 단일회귀
- 후보(순서대로): `Ridge`/`ElasticNet` → `RandomForestRegressor` → `HistGradientBoostingRegressor`(NaN 네이티브 처리, 유력 후보)
- `research/01_eda.ipynb` → `02_baseline_and_ridge.ipynb` → `03_tree_ensembles.ipynb`, 로직은 `service/model_training.py`로 승격
- `scripts/train_revenue_model.py`(학습+저장) / `scripts/predict_conversion_revenue.py`(무료작에 적용, 대시보드가 이 출력을 읽음)

## D. 대시보드 (`pages/`)

Streamlit `st.navigation`/`st.Page` API로 3페이지 구성:
- `pages/app.py`(진입점) → `_overview.py`(무료작 현황·학습셋 분포 비교), `_predictions.py`(예측 순위/필터), `_model_performance.py`(지표·베이스라인 비교)

## E. 테스트

크롤러 관련 테스트는 완료(28개). 추가 예정: `tests/service/` 하위에 `episode_features`/`target_builder`/`schema` 단위 테스트, `test_model_training.py`(작은 합성 데이터로 파이프라인이 끝까지 도는지 확인하는 스모크 테스트).
