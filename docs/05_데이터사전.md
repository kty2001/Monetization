# 데이터 사전

`data/` 아래에 생성되는 파일들의 컬럼 정의. 원본 API 필드명과의 매핑은 [크롤러](03_크롤러.md)의 "실제 사이트 조사 결과"도 함께 참고.

## 디렉토리 배치

성격이 다른 크롤은 **디렉토리를 분리**함(`CrawlCheckpoint.find_latest`가 디렉토리 안의 체크포인트를 mtime으로만 고르므로, 섞으면 `--resume`이 엉뚱한 걸 집음).

| 경로 | 내용 | 수집 규모 |
|---|---|---|
| `data/raw/` | nv.free 본 크롤 (`novels_*`, `episodes_*`) | 48,897작품 / 431,782회차 (run_id `20260810_231806`) |
| `data/raw/stats/` | nv.free 목록 통계 스냅샷 (`novel_stats_*`) | 2시점 — `20260811_165552`(48,864건) / `20260812_121713` |
| `data/raw/paid/` | pl.serial_end 라벨 본 크롤 (`paid_*`) | 9,252작품 / 234,058회차 (run_id `20260812_174443`) |
| `data/raw/paid_sample/` | pl.serial_end 사전 검증 샘플 (`paid_*`) | 20작품 / 5,613회차 (run_id `20260812_121403`) |
| `data/processed/` | 가공 데이터셋·모델·예측 | free 11,189건 / labeled 8,990건 |

> `data/`는 `.gitignore` 대상임. 클론 직후에는 비어 있으므로 [실행 가이드](07_실행가이드.md) 순서대로 크롤부터 실행해야 함.

## `novel_stats_{run_id}.csv` (`entity/novel_stats.py`, `scripts/crawl_munpia_stats.py`)

목록 API(`section=nv.free`/`pl.serial`/`pl.serial_end` 등)에서 얻는 좋아요/선호작/댓글/구매·대여 등 집계 필드. 작품 상세·회차 호출 없이 목록 페이지만 순회하므로 저비용임(본 크롤과 완전히 분리된 파일·체크포인트, 기본 출력 위치도 `data/raw/stats/`로 분리).

```bash
uv run python scripts/crawl_munpia_stats.py --section nv.free --delay 0.8 --resume
```

| 컬럼 | 타입 | 원본 필드 | 설명 |
|---|---|---|---|
| novel_id | str | `nvSrl` | 작품 고유 ID |
| section | str | — | 수집 대상 섹션(`nv.free`/`pl.serial`/`pl.serial_end`) |
| entry_count | int | `nvSumEntry` | 총 회차 수 |
| comment_count | int | `nvSumComment` | 총 댓글 수 |
| score | float | `nvSumScore` | 평점 |
| purchased_count | int | `nvSumPurchased` | **작품 전체 누적 구매 건수 — 회차당 수치가 아님** (`nv.free`는 항상 0). 예측 타겟(`target_paid_events_per_episode`)은 이 값을 유료 회차 수로 나눈 것임([모델 명세](06_모델.md) 1절). 매출 환산에 쓰는 회차 단가는 크롤·모델 어디에도 들어가지 않음 |
| rented_count | int | `nvSumRented` | 총 대여 수(타겟에는 미사용, `nv.free`는 항상 0) |
| hit_count | int | `nvSumHit` | 누적 조회수(무료+유료 기간 합산 — 유료작 피처로 직접 사용 금지, [로드맵](04_로드맵.md)의 누수 방지 원칙 참고. `nv.free`는 순수 무료 기간 값) |
| good_count | int | `nvSumGood` | **좋아요/추천 수** — `nv.free`에서도 실값 확인됨 |
| prefer_count | int | `nvSumPrefer` | **선호작(구독) 등록 수** — `nv.free`에서도 실값 확인됨 |
| char_count | int | `nvSumChar` | 총 글자 수 |
| genre_main / genre_sub | str | `nvGnMain`/`nvGnSub` | 장르 코드(숫자 — 문자열 장르명은 `novel-detail` 상세 호출로 별도 확보) |
| is_finished / is_adult / is_exclusive | bool | `nvOptFinish`/`nvOptAdult`/`nvOptExclusive` | 완결/성인/독점 여부 |
| crawled_at / run_id | str | — | 크롤 시각 / 실행 ID |

`novels_{run_id}.csv`와 `novel_id`로 join 가능함. `novel-detail` 상세 API의 `likeCount`/`preferenceCount`와 개념적으로 같은 지표를 목록 API 쪽(`nvSumGood`/`nvSumPrefer`)에서도 얻을 수 있어, 상세 API를 다시 호출하지 않고도 이 파일만으로 좋아요/구독 지표를 확보할 수 있음.

> **⚠️ join 시 양방향 누락 (2026-08-12 확인)**: `novel_stats_20260811_165552.csv`(48,864건)와 `novels_20260810_231806.csv`(48,897건)는 완전히 겹치지 않음.
>
> - stats에만 있고 novels에 없는 작품: **31건**
> - novels에만 있고 stats에 없는 작품: **64건** → join하면 이 64개 작품은 `good_count`/`prefer_count`가 결측이 됨
>
> 원인은 두 크롤 사이(하루 간격)에 신규 등록/삭제가 있었고, 목록 API의 정렬 순서가 크롤 도중에도 바뀌기 때문임(같은 이유로 전체 페이지를 훑어도 소수가 새어나감). 치명적이지 않으므로 `scripts/validate_raw_data.py`는 **warning**으로 보고함. 정제 단계에서 inner join으로 64건을 버릴지, left join으로 결측 처리할지는 미결.

## `paid_*` 파일 (유료 섹션)

`--section pl.serial_end --prefix paid_ --collect-stats`로 수집하면 위 세 파일과 **완전히 같은 스키마**로 `paid_novels_*` / `paid_episodes_*` / `paid_novel_stats_*`가 생김. 무료작 데이터셋과 동일한 정제·피처 함수를 그대로 적용하기 위한 설계임.

무료작과 다른 점은 값의 의미임 (본 크롤 9,252건 기준):

| | `nv.free` | `pl.serial_end` |
|---|---|---|
| `access_type` | 100% `FREE` | 앞 ~25화만 `FREE`, 나머지 `PAID` (무료 비율 5~16%) |
| 총 회차 수 중앙값 | 3화 | 200화 |
| 무료 회차 수 중앙값 | 3화 (= 전체) | **25화** (10% 23 / 90% 29 — 플랫폼이 정한 티저) |
| `purchased_count` | 항상 0 | 중앙값 63,929 (최대 17,120,177, 비-0 99.7%) |

> **⚠️ 무료 회차의 의미가 양쪽에서 다름.** 유료작의 무료 회차는 프로모션 티저이고 무료작의 무료 회차는 작품 전체임. 그래서 모든 피처를 **앞 10화 기준(`N=10`)** 으로 통일함 — 근거와 대안 비교는 [로드맵](04_로드맵.md) 핵심 결정 사항 참고.
>
> 또한 **완결 후 작가 후기가 마지막 회차에 무료로 붙는 경우**가 있음(샘플 20건 중 1건). 회차 최적화(`--free-chapters-only`)를 쓰면 자동으로 걸러지지만, 전체 회차를 받은 데이터로 피처를 만들 때는 앞쪽 연속 무료 구간만 쓸 것.

## `data/processed/` 가공 데이터셋 (`scripts/build_processed_dataset.py`)

`run_id`가 아니라 **`snapshot_date`(YYYYMMDD)** 로 누적 저장함(덮어쓰지 않음). 추론셋과 학습셋의 피처 컬럼이 동일함을 `service/schema.assert_feature_schema`가 저장 전에 강제함.

| 파일 | 내용 | 행 수 |
|---|---|---|
| `free_dataset_{YYYYMMDD}.csv` | 추론 대상(무료작). 타겟 없음 | 11,189 |
| `labeled_dataset_{YYYYMMDD}.csv` | 학습셋(유료 전환작). 타겟 포함 | 8,990 |

| 컬럼 | 구분 | 설명 |
|---|---|---|
| novel_id | 메타 | `data/raw/`의 CSV들과 join하는 키 |
| leading_free_episodes | 메타 | 선행 연속 무료 회차 수. **피처 아님** — 유료작은 플랫폼이 정한 티저 수(≈25 고정), 무료작은 작가가 쓴 전체 분량이라 의미가 다름 |
| genres | 피처(범주형) | 인코딩하지 않은 원본 문자열(쉼표 구분). 모델 파이프라인이 **쉼표로 쪼개 토큰 단위 multi-hot**으로 처리함 — 조합 그대로 one-hot하면 추론셋 15.5%가 미학습 조합이 됨 |
| free_views_1_10 | 피처(수치) | 앞 10화 조회수 합 |
| retention_1_to_10 | 피처(수치) | 10화 조회수 / 1화 조회수. 1화가 0이면 `NaN`(채우지 않음 — `HistGradientBoostingRegressor`가 네이티브 처리) |
| retention_1_to_3 | 피처(수치) | 3화 조회수 / 1화 조회수 (초반 이탈) |
| likes_1_10 / comments_1_10 | 피처(수치) | 앞 10화 좋아요 / 댓글 합 |
| target_paid_events_per_episode | 타겟 | **회차당** 구매 건수 = `purchased_count` ÷ 유료 회차 수. `labeled`에만 존재. 구매수 0/결측 작품은 제외됨. 유료 회차 수 = `chapter_count` − 수집한 선행 무료 회차 수 |

**포함 조건**: 선행 연속 무료 회차가 **10화 이상**인 작품만 들어감. 무료작 48,897건 중 11,189건(22.9%)이 해당하며, 나머지는 피처를 계산할 근거 자체가 없음(무료작 회차 수 중앙값 3화).

**제외한 컬럼과 이유 — 누수** (`service/novel_features.LEAKY_COLUMNS`): `total_view_count`, `chapter_count`, `like_count`, `preference_count`, 그리고 `NovelStats`의 `good_count`/`prefer_count`. 모두 유료작에서 무료 기간과 유료 기간이 섞여 타겟과 누수 관계이거나(누적 집계), 무료 시기 값만 분리할 수 없는 현재 시점 스냅샷임.

**제외한 컬럼과 이유 — 분포 불일치** (`service/novel_features.EXCLUDED_STATIC_COLUMNS`, 2026-08-13 추가): `serialization_status`는 학습셋 `완결` 100% / 추론셋 `연재중` 100%로 train/inference 분할과 완전히 교락돼 있고, `tags`는 결측률이 학습 56.2% vs 추론 35.0%로 달라 결측 자체가 covariate shift임. 상세는 [로드맵](04_로드맵.md) "범주형 피처" 참고.

## `data/processed/` 모델 산출물

| 파일 | 내용 |
|---|---|
| `revenue_model_{YYYYMMDD}.pkl` | 표준 `pickle` dict — `model`(적합된 파이프라인), `model_name`, `support_bounds`, `trained_at`, `training_rows` |
| `model_metrics_{YYYYMMDD}.json` | 베이스라인·후보 모델별 지표 전체 |
| `predictions_{YYYYMMDD}.csv` | 추론 결과 |

`predictions_{YYYYMMDD}.csv` 컬럼:

| 컬럼 | 설명 |
|---|---|
| novel_id | 작품 키 |
| predicted_paid_events_per_episode | **회차 1편당 예측 구매 건수**(작품 전체 합계가 아님). "유료 전환에 **성공했을 때의** 조건부 기댓값"이며 전환 확률 자체는 모델링하지 않음 |
| free_views_1_10 | 밴드 판정에 쓰인 값(진단용) |
| support_band | `정상`(학습셋 5~95% 구간, 16.0%) / `희박(하한 미만)`(84.0%) / `희박(상한 초과)`. 앱은 이 값을 반드시 노출할 것 |

매출(KRW) 환산은 이 파일에 없음 — `회차당 예상 매출 = predicted_paid_events_per_episode × 회차 단가`이고, 작품 전체 매출은 여기에 유료 연재 회차 수를 곱함. 단가는 앱에서 사용자가 입력함.

## `app/bundle/` 앱 번들 (`scripts/build_app_bundle.py`)

PyInstaller가 exe에 함께 묶는 파일들. 빌드 산출물이라 git에 포함하지 않음.

| 파일 | 내용 |
|---|---|
| `catalog.csv` | `predictions_*.csv` + `novels_*.csv`의 제목/작가/장르 (U+FEFF 제거, 예측값 내림차순) |
| `model.pkl` | 실시간 분석용 모델 — `revenue_model_*.pkl` 복사본 |
