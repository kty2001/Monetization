# 실행 가이드

클론한 리포지토리에서 데이터 수집 → 학습 → 배포용 exe 빌드까지의 상세 절차. 명령 요약만 필요하면 [README의 How to Use](../README.md#how-to-use) 참고.

## 0. 요구사항

| 항목 | 값 |
|---|---|
| Python | 3.13 이상 (`pyproject.toml`의 `requires-python`) |
| 패키지 관리 | [uv](https://docs.astral.sh/uv/getting-started/installation/) |
| OS | 데이터 파이프라인·학습은 OS 무관, **앱 빌드는 Windows 전용**(PyInstaller가 실행 OS용 바이너리를 만들고 빌드 스크립트가 PowerShell) |
| DB | 사용하지 않음 — 모든 데이터가 `data/` 아래 CSV |
| 네트워크 | 크롤 단계와 앱의 실시간 분석 기능에 필요 |

## 1. 설치

```bash
git clone <repository-url>
cd Monetization
uv sync
uv run pytest        # 설치 확인 — 129개 통과
```

`pyproject.toml`/`uv.lock`에 고정된 패키지가 `.venv`에 설치됨. 가상환경을 activate할 필요 없이 이후 모든 명령을 `uv run`으로 실행함.

크롤러 설정(User-Agent·요청 지연·재시도·타임아웃)을 바꾸려면 `.env.example`을 `.env`로 복사해 필요한 값만 채움. 비워두면 `clawler/config.py`의 기본값이 쓰이므로 **생략 가능**. 상세는 [환경설정](01_환경설정.md) 참고.

## 2. 데이터 수집

> ⚠️ **`data/`는 `.gitignore` 대상이라 클론 직후에는 비어 있음.** 아래 크롤을 직접 돌려야 함. 이미 수집된 CSV가 있다면 [데이터 사전](05_데이터사전.md)의 "디렉토리 배치"대로 배치하고 3단계로 건너뜀.

### 추론 대상 — 무료 자유연재

```bash
uv run python scripts/crawl_munpia.py --max-pages 0 --novel-limit 0 --delay 0.8 --resume
```

### 학습셋 라벨 — 유료 전환 완결작

```bash
uv run python scripts/crawl_munpia.py --section pl.serial_end --prefix paid_ \
  --collect-stats --free-chapters-only --max-pages 0 --novel-limit 0 --delay 0.8 \
  --output-dir data/raw/paid
```

`--output-dir`를 반드시 분리할 것. 체크포인트가 디렉토리 단위라 같은 곳에 쓰면 `--resume`이 엉뚱한 체크포인트를 집어 데이터가 섞임.

### 목록 통계 스냅샷

```bash
uv run python scripts/crawl_munpia_stats.py --max-pages 200 --delay 0.8
```

목록이 최신순 정렬이라 앞 200페이지면 충분함. 이후 월 1회 운영하며, 근거는 [크롤러](03_크롤러.md) "정기 스냅샷 운영" 참고.

### 주의사항

- **`--max-pages 0`을 빠뜨리면 조용히 1페이지(20건)만 수집하고 정상 종료함.** 기본값이 1이므로 전체 크롤에는 반드시 붙일 것
- `--delay`를 줄이면 빨라지지만 서버 부하가 커짐. 403/429를 받으면 재시도 없이 즉시 크롤 전체가 중단됨(`BlockedByServerError`)
- 소규모 동작 확인은 `--max-pages 1 --novel-limit 5`로 먼저 해볼 것

### 중단과 재개

크롤은 작품 단위로 CSV에 즉시 append하고 체크포인트를 남기므로, 중단돼도 그때까지 수집분은 보존됨.

```bash
# 같은 명령에 --resume을 붙여 재개
uv run python scripts/crawl_munpia.py --max-pages 0 --novel-limit 0 --delay 0.8 --resume

# 많이 진행된 상태라면 --start-page로 앞 페이지 재스캔을 건너뜀 (처리 건수 ÷ 20에서 여유를 둠)
uv run python scripts/crawl_munpia.py --max-pages 0 --novel-limit 0 --delay 0.8 --resume --start-page 1700
```

장시간 크롤은 프로세스가 외부 요인으로 종료될 수 있어 워치독과 함께 돌리는 편이 안전함.

```powershell
powershell -File scripts/watch_and_resume.ps1 -OutputDir data/raw/paid `
  -ExtraArgs '--section pl.serial_end --prefix paid_ --collect-stats --free-chapters-only --max-pages 0 --novel-limit 0 --delay 0.8'
```

옵션 전체·재개 동작·워치독 설계는 [크롤러](03_크롤러.md), [로드맵 F](04_로드맵.md) 참고.

## 3. 데이터 검증

```bash
uv run python scripts/validate_raw_data.py
uv run python scripts/validate_raw_data.py --prefix paid_ --data-dir data/raw/paid --stats-dir data/raw/paid
```

ID 중복·음수 값·참조 무결성 위반이 있으면 종료코드 1. 재개 과정에서 중복 작품 행이 생길 수 있으므로 **크롤 종료 후 항상 실행할 것**. 검사 항목은 [크롤러](03_크롤러.md) "데이터 품질 검증" 참고.

## 4. 데이터셋 생성

```bash
uv run python scripts/build_processed_dataset.py --free
uv run python scripts/build_processed_dataset.py --labeled \
  --data-dir data/raw/paid --stats-dir data/raw/paid --prefix paid_
```

`data/processed/{free|labeled}_dataset_{YYYYMMDD}.csv`가 생성됨. 두 데이터셋의 피처 컬럼이 동일함을 `assert_feature_schema`가 저장 전에 강제하므로, 스키마가 어긋나면 여기서 예외로 드러남. 피처 기준 회차 수는 `--n-episodes`로 바꿀 수 있음(기본 10).

## 5. 학습과 추론

```bash
uv run python scripts/train_revenue_model.py         # → revenue_model_{date}.pkl, model_metrics_{date}.json
uv run python scripts/predict_conversion_revenue.py  # → predictions_{date}.csv
```

베이스라인과 후보 모델(`ridge`/`elasticnet`/`random_forest`/`hist_gbr`)을 비교해 최적 모델을 저장함. 일부만 학습하려면 `--only hist_gbr`. 추론 출력에는 `support_band`(학습 데이터 밀도 밴드) 라벨이 함께 붙음.

피처·하이퍼파라미터·성능·한계는 [모델 명세](06_모델.md) 참고.

## 6. 데스크톱 앱 빌드 (Windows)

```powershell
powershell -File scripts/build_desktop_app.ps1
```

번들 생성(카탈로그+모델) → 스플래시 이미지 → PyInstaller onefile 빌드 → 빌드본 자체 점검(`--selftest`)을 한 번에 실행함. 산출물은 **`dist/MunpiaRevenue.exe` 하나**이며, 이 파일만 전달하면 실행됨(작가용 안내문 `dist/사용법.txt`는 선택적으로 동봉).

- 자체 점검이 모델 언피클과 `model.predict`까지 확인하므로 `RESULT: OK`가 아니면 빌드가 실패함 — 배포본에서만 죽는 패키징 오류를 여기서 잡음
- 서명되지 않은 exe라 첫 실행 시 SmartScreen "알 수 없는 게시자" 경고가 뜸. 대응 절차는 `사용법.txt`에 기재
- onefile이라 실행할 때마다 ~150MB를 `%TEMP%`에 푸느라 메인 창까지 7~8초가 걸림. 그동안 스플래시가 표시됨

설계 배경은 [로드맵 D](04_로드맵.md) 참고.

## 개발용 실행

빌드 없이 앱 화면만 확인하려면 번들만 만들고 직접 실행함(`app/main.py`가 `app/bundle/`을 읽음).

```bash
uv run python scripts/build_app_bundle.py
uv run python app/main.py
```

노트북 실험은 `research/01_eda.ipynb` → `02_baseline_and_linear.ipynb` → `03_tree_ensembles.ipynb` 순서이며, 로직은 전부 `service/model_training.py`에 있고 노트북은 호출만 함.

```bash
uv run jupyter lab
```

## 문제 해결

| 증상 | 원인과 대응 |
|---|---|
| 크롤이 20건만 수집하고 정상 종료 | `--max-pages` 기본값이 1임. `--max-pages 0`을 붙일 것 |
| `BlockedByServerError`로 즉시 중단 | 403/429 응답. `--delay`를 늘리고 시간을 두고 재시도 |
| `--resume`이 엉뚱한 데이터를 이어씀 | 성격이 다른 크롤이 같은 `--output-dir`를 씀. 디렉토리를 분리할 것 |
| 검증에서 `novel_id` 중복 error | 재개 시점에 따라 생기는 중복 행. 해당 행을 정리한 뒤 진행 |
| 데이터셋 생성이 스키마 예외로 실패 | 학습셋/추론셋 피처 컬럼 불일치. `service/schema.py`의 `FEATURE_COLUMNS` 확인 |
| 빌드 자체 점검이 `RESULT: OK`가 아님 | 모델 언피클 실패. `app/munpia_app.spec`의 `hiddenimports`에 `service.model_training`이 있는지 확인 |
| 앱 실행 시 번들을 찾지 못함 | `scripts/build_app_bundle.py`를 먼저 실행할 것 |
